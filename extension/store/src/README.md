# Rebuilding the Link store art

Run `pnpm run store:art` with the assigned stand-in and worker ports. It builds the site and Link, captures current UI in Playwright's Chromium, then renders the five 1280 × 800 screenshots, 440 × 280 tile and 1400 × 560 marquee. `public/logo-mark.svg` is the mark source. `public/brand/obpal-link-lockup.svg` outlines the existing header typography and LINK pill; site headers, the phone, popup and options reference the same asset. `python scripts/link-lockup.py` regenerates it using the bundled OFL fonts (fontTools with Brotli), with base and light-surface views. The logo is rendered as vector at each final display size; the store icon is the package icon, with 96 px art and 16 px transparent padding. Do not replace it with a redraw. `node scripts/brand-icons.mjs` derives the site raster icons from that canonical SVG without rewriting it.

`motif.mjs` draws finished glass device bodies: the canonical cube inside the browser and a real controller capture inside the phone, joined by a still dot wave sampled at equal arc-length intervals. This is brand illustration, not a new connection protocol or an animation claim. The optional PC route appears only in its labeled Windows screenshot. `scenes.mjs`, `poster.mjs` and `shot.mjs` keep the Carbon glass composition, short captions and current capture crops reproducible. There are no third-party game images or marks.

UI is captured at device pixel ratio 3. Raster crops are checked against their display widths and never enlarged. Screenshot 2 shows the actual built 3D viewer and trackpad. The tile shows the Wii-style pointer; the marquee leads with the trackpad. Screenshots 1 and 3 use the gamepad for the standard Gamepad API and Keys mapping respectively. The keyboard dock is offered only in PC mode, so screenshot 4 shows it beside the air mouse rather than claiming typing in Keys mode. Caption text is at least 23 px on the 1280 × 800 images. The pairing and trust captures use a real locally paired link and matching seals. The public QR picture holds the site's address rather than a live room. The PC picture stages the current popup's native state; it does not start or test the installed helper. The phone is desktop-emulated. A seal is a comparison aid, not certification or input permission.

Raw captures use `rawRun(out)` in TEMP and are distilled by default. For crop iteration, set `OBPAL_STORE_KEEP_CAPTURES=1`, then use the printed TEMP directory as `OBPAL_STORE_CAPTURES`; distil the evidence afterward. `node extension/store/src/proof.mjs` creates the before (a4f0ff0), R4 (d48810b) and R5 image sheet, plus the icon comparison sheet under ignored `artifacts/link-1.8/`.

Chrome's [image guidance](https://developer.chrome.com/docs/webstore/images) specifies icon padding, light/dark legibility, promo sizes and full-bleed screenshots. Its [listing guidance](https://developer.chrome.com/docs/webstore/best-listing) asks for simple recognizable branding, readable thumbnails and accurate feature depictions. The no-text promo advice is balanced here with the established wordmark and one short headline. All caption text sits on Carbon with at least 4.5:1 contrast; current UI captures retain their own family surfaces.

The renderer rejects any glass device outside a 16 px frame margin (20 px for screenshot phones). The tile keeps a large 344 px shared lockup with a lighter visual footprint and a complete phone inside the frame. GPU captures must hold the shared lease from `scripts/lib/gpu-lease.mjs`; probe with `detectE2eGpu`, keep `OBPAL_E2E_GPU=1` for hardware or its measured SwiftShader fallback, and release after browser cleanup. The store kit uses `../store/` image references relative to `extension/release/store-kit.html`. Art-only changes do not rebuild the store zip.
