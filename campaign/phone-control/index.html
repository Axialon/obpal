A scope you can assess.

One existing browser experience, one participant task and one current input baseline. Source review, task-to-SDK mapping, honest evidence status, recovery guidance and one correction round form the proposed scope.

What the review would deliver

  • A readable readiness report with a go, test first or do not use recommendation.
  • An annotated integration sketch and a repeatable test-and-observation card.
  • Named limits, unverified conditions and the next implementation decision.

How to assess it

Each agreed task requirement maps to an SDK capability or an explicit gap. Every device and compatibility statement has an evidence status. The report explains its baseline, recommendation and recovery path.

Acceptance concerns the review's completeness and correctness. It does not guarantee successful integration or user adoption.

Limits before a commitment.

No buyer build installation, deployment, hardware or robotics work, extension/native PC permissions, universal compatibility, latency guarantee, hosting or ongoing maintenance is included. A physical-phone trial stays unverified unless actually performed or supplied with permission.

The sample is a source-informed review, not a customer engagement or a paid result. It does not prove a buyer integration. Operator, capacity, fixed quote, currency, dates and commercial terms remain unestablished.

The field guide is open to read. A service, if separately agreed, would be optional.
