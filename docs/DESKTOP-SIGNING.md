# Signing ob.Pal Desktop

Research checked 30 September 2026. Desktop remains unsigned. No account was opened, identity documents submitted, certificate purchased or binary signed in this run.

Signing would give the Windows executable a verified publisher and detect changes after signing. New signed releases can still receive SmartScreen warnings while reputation builds; EV certificates no longer grant an immediate bypass. Smart App Control and enterprise policies can also block unsigned apps. The companion therefore describes the current warning without promising that an install is safe or advising users to disable protection. [Microsoft: SmartScreen reputation](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation).

Microsoft currently lists Azure public signing for organizations in the US, Canada, EU and UK, and individuals in the US and Canada. Australia is absent from that eligibility list. A resource hosted in an available Azure region does not establish publisher eligibility. Confirm the legal publisher's country before choosing this route. [Microsoft eligibility](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options).

SSL.com documents individual and organization validation and cloud-HSM signing as alternatives; its individual certificate displays a personal publisher identity. Its current product pages did not expose a reliable total price in this research, so no numerical vendor quote is asserted. [Certificate options](https://www.ssl.com/products/software-integrity/code-signing/), [Cloud service](https://www.ssl.com/products/software-integrity/signing-service/).

Recommended next action: check SignPath acceptance and the intended publisher, then obtain a CA quote if needed. Use Azure Basic only if that publisher is eligible. Paying an EV premium solely to suppress SmartScreen is unjustified. Keep unsigned-release messaging until the shipped artifact is actually signed and verified.

Planning estimate, not a provider promise: allow two working days to prepare publisher and project evidence; Azure documents 1–20 business days for validation, possibly longer. Reserve another two to four engineering days after approval for an isolated signing stage, timestamping, signature verification, zip checks and installation testing on a disposable Windows machine. SignPath publishes no guaranteed approval deadline here; CA validation and hardware delivery require a quote. [Azure validation timing](https://learn.microsoft.com/en-us/azure/artifact-signing/quickstart).

The future release lane should sign the final `obpal-desktop.exe`, timestamp it, verify Authenticode and publisher identity, then package it without changing the signed bytes. Keep signing credentials outside the repository. Publish checksums and the exact publisher label in the companion only after release verification. A `.cmd` install wrapper remains a separate visible script; signing the executable does not turn that script into a signed installer.

Owner decision: select the legal publisher and approve a signing route and spending ceiling after eligibility or a quote is confirmed. This document authorizes no purchase, registration or signing.
