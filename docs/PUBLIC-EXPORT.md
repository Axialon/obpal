# Public demo export

Installing the exporter in development does not admit newer private runtime or assets into the public profile.
Unknown paths and stale pinned inputs refuse export. Reconcile their source in a separate reviewed policy; never
repin runtime or assets merely to make an export pass.

`public-demo-v1` is generated from the development source, not maintained as a separate application. Its Viewer contains the existing procedural cube, knot and gem. Cube is the default, including fallback from an unavailable saved selection. Studio and Local remain; Local loads files explicitly chosen on that device. Arena uses its existing neutral pucks labelled Team 1–4. Other simulations retain individually classified original prototype meshes, runtime audio and required vendor assets.

The profile excludes CVC/Blackboxes depictions, their catalogue helpers, unverified promotional screenshots and the six campaign films/posters. The campaign entry retains its page/share shell and explains that films are omitted; the compatible film manifest is empty. It supplies no replacement films or restricted asset pack. Development originals are untouched. The original CVC notice is retained solely as context; it does not license omitted assets. Original root licences, trademark policy, font notices, MediaPipe notice and audio credits remain unchanged.

Coaching task definitions, fixtures, attempts, adapters, evidence recorders and clients are outside this profile and require a separate public-scope review. General development scripts and historical tests can describe development-only assets. The historical image-generation command imports a helper absent from the frozen baseline and is excluded. Its original card/phone sources and the separately classified static preview retain their existing classifications. Build, CPU and browser receipts identify the exact source they tested. Physical-device acceptance has its own evidence record.

The development film-transport, partner-film, store-art and store-manager suites depend on omitted media, held artwork
or private submission history and remain outside the public profile. Their original source and prior evidence stay in
development. Public export contracts verify the empty film inventory and route, campaign omission, asset exclusions and
privacy boundary. Full public CPU results describe the tests included in this finite profile.

The public listing comparison also exercises a synthetic changed field and the icon comparator rejects mismatched
framing. Two historical-only cases, submitted-listing differences and the older store redraw, are explicitly skipped
when the generated policy has a null payload revision. Development retains both original historical assertions.

## Inputs and output

The exact allowlist contains no include globs. Each tracked path must be included or explicitly excluded; an unknown tracked path fails. Included rows have a role, rights basis, original notice paths and pinned SHA-256. Asset rows also identify their original authoring source or vendor provenance; code's MIT licence does not automatically cover assets. Restricted digests cannot enter under a renamed or relabelled path.

The private development policy pins a reviewed runtime Git revision independently of new export tooling. Export reads immutable Git blobs, verifies input hashes and requires the working tree/index to match the tooling commit. It checks raw working bytes, index bytes and HEAD again after materialization and staging. Symlink/reparse-point inputs and outputs, traversal, collisions, missing files, extras and changed bytes fail closed. Commit intentional changes and review their classification/hashes before exporting again.

Only the declared Wrangler, catalogue, Arena, campaign, film-manifest, Worker film-inventory and policy projections may change bytes. Catalogue selection uses the installed TypeScript parser and named canonical bindings; unfamiliar structures require review. Existing primitive builder bodies and the development catalogue behavior are preserved. Wrangler exports inert self-host defaults, without operator destinations, contribution database or active payment settings. Follow [SELF-HOSTING.md](SELF-HOSTING.md) to configure a service you operate.

One materialization produces `public-export.manifest.json`: each output path, source/output hashes, byte length, Git executable mode, role and notices. Modes come from the row's immutable source tree, independently of the tooling checkout. POSIX output modes are checked; publication staging also writes and verifies Git index modes, including on Windows where chmod alone is insufficient. The manifest's own checksum is recorded externally to avoid recursive hashing. Scanning and staging verify the same inventory, including generated files and metadata; staging never returns to the original tracked list. The existing scanner checks all real bytes. Only the two named MediaPipe WASM files qualify for its existing binary exception, and only when byte-identical to their installed package copies. No other asset receives that exception.

Public policy metadata describes included, projected inputs only. Private omission records and operational/source receipts remain outside the exported tree. The generated policy uses the public checkout's own Git revision, so reproduction does not require private history. Runtime bytes are deterministic; the source provenance and manifest hash can change when the same public tree is committed under a different tooling/policy revision.

## Reproduce locally

Use Node 22.23 or newer and the package-manager version declared in `package.json`.

```sh
pnpm install --frozen-lockfile
node scripts/open-source.mjs --keep-logs
```

The command prints an owned temporary output path. Without `--keep-logs`, it removes its output after checking. From the retained profile, install its pinned dependencies if needed and run `pnpm run build`; set `OBPAL_PUBLIC_ORIGIN` only to a service you control. A standalone export is not a Git checkout: commit its finite inventory before exporting it again. Review the generated manifest separately from build outputs. Never copy the development dependency directory into a distributable tree.

Focused contracts are `tests/public-export-policy.test.ts`, `tests/public-catalog.test.ts` and `tests/public-export.test.ts`. Their fixtures use temporary repositories and local staging. Publication fixtures exercise the native entry point against a TEMP bare repository, with a preload that refuses external commands and destinations. Source/import/asset/notice closure, a fresh build, and any guarded paired-browser smoke are separate gates. Browser checks must use the existing native helper guard and FIFO GPU lease, respecting other holders. A deferred smoke remains pending, not passing.

## Publication and history

Local source, tested source, integration, generated output and deployed revisions are distinct. Neither a passing test nor a clean export changes a live service. Publishing requires a fresh exact-tree review, rights/history disposition, explicit existing repository/public identity configuration and full source/tree/public-main pins. The native publisher checks the existing public repository and baseline again before its single normal fast-forward push, then fetches the published commit and tree for readback. Deployment, provider credentials, payments, mail, indexing and spending require their own authorization.

An earlier public snapshot contains restricted assets in reachable history. Omitting them from a newly generated tree does **not** erase those historical blobs. This exporter does not rewrite history, force-push, change licences or create a new destination. Publication remains held until the owner resolves that historical scope explicitly.
